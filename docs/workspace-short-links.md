# ลิงก์สั้นประจำ Space

ทุกหน้าทำงานแสดงชื่อ Space ใน URL หลัง Login ระบบตรวจสมาชิกและเปิด Space ตามลิงก์ โดยไม่ใช้ Space ล่าสุดแทนทีมที่ระบุ

| หน้า | ตัวอย่าง URL |
| --- | --- |
| ภาพรวมงาน | `https://happy-victory-task-center.vercel.app/rinlyn` |
| รายการงาน | `/rinlyn/tasks` |
| งานเข้าใหม่ | `/rinlyn/inbox` |
| ส่งงานใหม่ | `/rinlyn/tasks/new` |
| ลงทะเบียนตัวแทน | `/rinlyn/register` |
| รายละเอียดงาน | `/rinlyn/tasks/rec…` |
| เอกสาร | `/rinlyn/forms` |
| เปิดเอกสาร | `/rinlyn/forms/<document-id>/open` |

ปฏิทิน งานติดตาม รายงาน ทีม ประวัติ และการแจ้งเตือนใช้ prefix เดียวกัน เปิดคนละ Space พร้อมกันหลายแท็บได้ โดยแต่ละแท็บอ่าน/บันทึกตาม URL ของตน การเข้า `/` หรือ URL งานเก่าที่ไม่ระบุ Space จะตรวจ Space ล่าสุดแล้วนำไป URL ที่ระบุทีม

## คัดลอกและสร้างลิงก์

1. เปิดหน้า **เลือก Space** แล้วกด **คัดลอกลิงก์** ของทีมที่ต้องการ
2. เมื่อสร้าง Space ใหม่ Owner กำหนดช่อง **ชื่อสำหรับ URL** เป็นอังกฤษตัวเล็ก ตัวเลข และขีดกลาง เช่น `rinlyn-team` ได้
3. หากเว้นว่าง ระบบสร้างจากชื่อ Space; ชื่อที่ไม่มีตัวอังกฤษ/ตัวเลขจะใช้ `space-<รหัส>` แทน จึงแนะนำระบุชื่อ URL สำหรับทีมที่ใช้ชื่อไทย
4. ชื่อซ้ำเติมเลขท้าย เช่น `rinlyn-2` ชื่อเมนูระบบ เช่น `tasks` ใช้เป็นชื่อ URL ไม่ได้

การเปลี่ยนชื่อแสดงผลของ Space ไม่เปลี่ยนลิงก์ ลิงก์ไม่ใช่สิทธิ์เข้าถึง สมาชิกยังต้องผ่าน Google Login และ Active ทั้งบัญชี/สมาชิก/Space ผู้ไม่เป็นสมาชิกจะไม่ได้รับข้อมูลงาน ไม่มีการสลับไป Space อื่นเมื่อเปิดลิงก์ที่ไม่มีสิทธิ์

ลิงก์ใหม่จาก LINE ใช้ URL ที่ระบุ Space รวมถึงลิงก์เอกสารที่เปิดแท็บใหม่ ลิงก์ UUID เดิมยังเลือกทีมแล้วนำไป URL ใหม่ได้ ลิงก์ลงทะเบียนยังใช้ได้ตามเดิม การเปิดลิงก์เว็บไม่เปลี่ยน Space ของ LINE AI

## ติดตั้ง

ใช้ migration `015_workspace_slugs.sql` ก่อน deploy เว็บ ตารางกลาง Neon ได้คอลัมน์ `hvr_workspaces.slug` พร้อม unique index แยก environment และ trigger จัดชื่อที่ไม่ชนกัน ไม่เพิ่มฟิลด์ใน Airtable ไม่รวม migration นี้ใน operational schema ของแต่ละ Space

ตรวจผล backfill ก่อนเปิดใช้งาน เช่น `RINLYN` → `rinlyn` และทดสอบชื่อซ้ำ/ชื่อเมนู/ชื่อไทย, Login return path, สมาชิกถูกถอนสิทธิ์ และลิงก์ UUID เดิม การย้อน release ให้คงคอลัมน์/index/trigger ไว้เพื่อรักษาลิงก์ที่แจกไปแล้ว

รุ่นที่แสดง Space ทุกหน้าใช้ migration 015 เดิม ไม่ต้องเปลี่ยน schema เพิ่ม คำขอ API ส่ง `X-Workspace-Slug` จาก URL; เซิร์ฟเวอร์ค้น Space แล้วตรวจสิทธิ์ใหม่ทุกครั้ง ไม่ถือ header เป็นสิทธิ์ และตรวจ `X-Workspace-Id` กับ CSRF ที่ผูกกับ Space ก่อนบันทึก ลิงก์เปิดเอกสารตรวจจาก route parameter โดยตรง คำขอรุ่นเก่าที่ไม่มี slug ยังตรวจ cookie/Space ล่าสุดและปฏิเสธ ID ที่ไม่ตรงกัน

# ประเภทงานและขั้นตอนติดตาม

เว็บรับงานใหม่ 4 ประเภท: **ตัวแทนใหม่, ตัวแทนเก่า, ลูกค้าใหม่, ลูกค้าเก่า** แต่ละประเภทมีสีแยกกันในรายการงาน ปฏิทิน และ LINE งานด่วนมากยังใช้ป้ายแดงเพื่อให้เห็นความเร่งด่วนชัดเจน

## วิธีใช้งาน

รายการงานแยก **งานที่ต้องทำ**, **ชื่อตัวแทน/ลูกค้า (เคส)** และ **Agent เจ้าของงาน** พร้อมแสดงชื่อเต็ม บนจอเล็กและ iPad ชื่องานจะอยู่บรรทัดบน ส่วนชื่อเคสและเจ้าของอยู่ด้านล่าง สถานะ ความเร่งด่วน และวันที่มีป้ายกำกับแยกในท้ายรายการ ใช้ได้ทั้งมุมมองรายการและการ์ด

1. Agent เลือกประเภทตอนส่งงาน และกรอก **ชื่อตัวแทน** (ตัวแทนใหม่/เก่า) หรือ **ชื่อลูกค้า** (ลูกค้าใหม่/เก่า) ช่องนี้บังคับกรอก มี * สีแดง และแยกจาก Agent เจ้าของงาน ระบบผูกเจ้าของงานกับบัญชีผู้ส่ง (ผู้จัดการเลือกเจ้าของได้) ชื่อบุคคลแสดงในรายการ/รายละเอียดงานและค้นหาได้ เลขาแก้ไขได้ที่ **แก้ไขข้อมูลงาน** งานเดิมที่ยังไม่มีชื่อยังเปิดดูได้
   สำหรับ LINE ถ้าร่างยังไม่มีชื่อ ระบบจะถามเพิ่ม ให้ตอบ เช่น `ชื่อลูกค้า: สมชาย ใจดี` แล้วตรวจร่างและกดยืนยัน
2. เลขาหรือ Admin เปิดงาน → **ขั้นตอนงาน** → กรอกข้อมูลประกอบเคส
   ทุกประเภทจัดข้อมูลเป็น **2 คอลัมน์แนวตั้ง** เรียงช่องลงมาเป็นคู่ ๆ และปรับเป็นคอลัมน์เดียวบนมือถือจอแคบ สำหรับตัวแทนใหม่ ผลการอบรมเลือก **ผ่าน / ไม่ผ่าน** และไม่มีช่องผลสอบ/ผลสอบเดิม
3. ติ๊กเช็กลิสต์เมื่อทำเสร็จ เอาติ๊กออกเมื่อต้องติดตามอีก กด **ตั้งวันติดตาม** เพื่อเปิดช่องวันที่ แล้วกด **บันทึกการเปลี่ยนแปลง** ที่แถบด้านล่าง ทุกประเภทไม่มีช่องหมายเหตุ/หลักฐาน/เหตุผลรายขั้นตอน
4. รายการที่ขึ้นกับเคส เช่น CTF, Memo, ตรวจสุขภาพ หรือ Go for Team กด **ไม่เกี่ยวข้อง** ได้โดยไม่ต้องกรอกเหตุผล และกด **นำกลับมาติดตาม** เพื่อยกเลิก ส่วนรายการบังคับที่ไม่มีเงื่อนไขข้ามไม่ได้
5. เมื่อรายการบังคับและข้อมูลประกอบครบ จึงเปลี่ยนสถานะงานเป็น **เสร็จสิ้น** ระบบแจ้ง LINE เจ้าของงานที่เชื่อมและเปิดรับไว้ตามเดิม

ช่องข้อมูลประกอบเคสที่มี **\* สีแดง** ต้องกรอกก่อนปิดงาน แต่ยังบันทึกความคืบหน้าระหว่างทำได้แม้กรอกไม่ครบ เครื่องหมายใช้รายการเดียวกับเงื่อนไขตรวจปิดงานใน `caseRequiredFields` ไม่ได้เพิ่มข้อบังคับใหม่ หลังกรอกให้กด **บันทึกการเปลี่ยนแปลง** ก่อนเลือก **เสร็จสิ้น** แล้วกด **บันทึกสถานะ**

| ประเภท | Checklist ที่ต้องจัดการก่อนปิด | ช่องข้อมูลบังคับ |
| --- | --- | --- |
| ตัวแทนใหม่ | 19 รายการในช่วง 1.1, 1.2 และ 1.3 จนลงทะเบียน Smart Start / HiPro; การเข้าเรียน First App และช่วง 1.4 ติดตามต่อได้ | ประเภทสมัครอบรม/สอบ, รหัสตัวแทนที่ออกแล้ว |
| ตัวแทนเก่า | 6 รายการ; 3 รายการ Go for Team/AL เลือกไม่เกี่ยวข้องได้ตามเคส | เป้าหมาย PC, ยอด PC สะสม, วันครบกำหนดรักษาสัญญา |
| ลูกค้าใหม่ | 15 รายการก่อนและหลังอนุมัติ; Memo, ประวัติ/ตรวจสุขภาพ และ CTF เลือกไม่เกี่ยวข้องได้ตามเคส | เลขที่ใบคำขอ, วันที่ส่ง, วันเริ่ม Freelook ตามเอกสารบริษัท, วันครบกำหนดเบี้ยปีถัดไป, หลักฐานการส่งมอบ/ที่เก็บเอกสาร |
| ลูกค้าเก่า | 5 รายการ; การแจ้งปัญหาติดต่อ/ชำระเลือกไม่เกี่ยวข้องได้เมื่อไม่มีปัญหาจริง | ยอดเบี้ย, วันครบกำหนด, ช่องทางชำระ, วันที่ยืนยันชำระแล้ว |

Checklist ครบ เช่น 15/15 ยังไม่พอถ้าข้อมูลบังคับว่าง เปิด **รายการที่ต้องครบก่อนปิดงาน** เพื่อตรวจรายการที่ขาด ห้ามติ๊กเสร็จหรือเลือกไม่เกี่ยวข้องเพียงเพื่อข้ามเงื่อนไขโดยยังไม่ได้ดำเนินการจริง

เมื่อเปิดหน้างาน ช่วงที่ครบแล้วจะพับไว้และเปิดช่วงแรกที่ยังไม่ครบ สามารถกดหัวข้อเพื่อดูช่วงอื่นได้ สรุป **ติดตามถัดไป** แสดงวันที่ใกล้ที่สุดของรายการที่ยังไม่เสร็จ การติ๊กและแก้วันที่ยังไม่ถูกบันทึกจนกดปุ่มบันทึก

หมายเหตุ ข้อมูลประกอบ และประวัติการแก้ไขเห็นเฉพาะเลขา/Admin; Agent เห็นยอดความคืบหน้ารายช่วงของงานตัวเอง บันทึกแต่ละครั้งมีผู้แก้ไขและเวลา หากมีคนอื่นแก้พร้อมกันต้องโหลดข้อมูลใหม่

## แก้ไขข้อมูลงาน

Admin และเลขาเปิดรายละเอียดงาน → **แก้ไขข้อมูลงาน** เพื่อแก้ชื่องาน รายละเอียด Agent เจ้าของงาน ความเร่งด่วน และกำหนดส่ง แล้วกด **บันทึกข้อมูลงาน** หรือยกเลิกเพื่อทิ้งการแก้ไข ใช้ได้กับงานที่ปิดแล้วด้วยโดยไม่เปลี่ยนสถานะหรือเช็กลิสต์

เจ้าของใหม่ต้องเป็น Agent ที่เปิดใช้งาน เมื่อบันทึก Agent เดิมจะหมดสิทธิ์ดูงาน และ Agent ใหม่จะเห็นงานพร้อมประวัติที่เปิดให้ Agent เห็น ระบบบันทึกผู้แก้ไข เวลา และชื่อช่องที่เปลี่ยน หากมีคนแก้งานไปก่อน ระบบให้โหลดข้อมูลใหม่แทนการเขียนทับ การแก้ข้อมูลอย่างเดียวไม่ส่งแจ้งเตือนงานใหม่หรือแจ้งเสร็จซ้ำ

## กติกาตัวแทนใหม่

ช่วงเตรียมสมัคร–อบรม–สอบและช่วงขอออกรหัสต้องครบ ช่วงต้อนรับบังคับถึง Greeting นามบัตร การยืนยันคอนเทนต์ ติดตั้งแอป และลงทะเบียน **Smart Start กับ HiPro** จึงปิดงานหลักได้ ต้องระบุประเภทสมัครและรหัสตัวแทนที่ออกแล้วด้วย

การเข้าเรียนทั้งสองหลักสูตร, First App, คอนเทนต์ฉลอง และ IC/Unit Linked เป็นการติดตามต่อ ไม่ขวางการปิดงานหลัก เลขายังแก้รายการเหล่านี้ได้หลังสถานะเสร็จสิ้น เมื่อตั้งวันติดตาม งานจะปรากฏใน **นัดติดตาม** และปฏิทิน การบันทึกขั้นตอนต่อไม่สร้าง LINE “งานเสร็จ” ซ้ำ

ทุกขั้นตอนของ **ทุกประเภทงาน** แสดงเฉพาะสถานะและวันติดตาม ไม่มีช่องหมายเหตุ/หลักฐาน/เหตุผล รายการทางเลือกเลือก **ไม่เกี่ยวข้องกับเคสนี้** ได้โดยไม่ต้องกรอกเหตุผล รายการบังคับยังข้ามไม่ได้ ข้อมูลประกอบเคสและกติกาปิดงานยังใช้ตามเดิม

## งานประเภทอื่น

- **ตัวแทนเก่า:** เป้าหมายเริ่มต้น 48,000 PC ปรับได้ตามแม่ตาล ระบุยอดสะสมและกำหนด ระบบคำนวณยอดขาด Go for Team ใช้เกณฑ์ที่ทีมกรอก
- **ลูกค้าใหม่:** มีช่วงยื่นแอปและส่งมอบกรมธรรม์ บันทึกเลขคำขอ วันส่ง วันเริ่ม Freelook ตามเอกสารบริษัท เบี้ยปีถัดไป และหลักฐานส่งมอบ
- **ลูกค้าเก่า:** ติดตามยอดเบี้ย กำหนด ช่องทางชำระ และวันที่ยืนยันชำระ

วันติดตามเป็นรายการงานให้เลขาดำเนินการ ระบบไม่ได้ส่งคำอวยพร สมัครอบรม ส่งเอกสาร หรือแจ้งลูกค้าแทนโดยอัตโนมัติ รายการเอกสาร 4 ใบและเกณฑ์บริษัทต้องตรวจจากเอกสารที่ทีมใช้งานจริง

## ข้อมูลเดิมและการติดตั้ง

ก่อน deploy รุ่นที่มีชื่อบุคคล ให้เพิ่ม `Tasks.Case Name` ชนิด **Single line text** ใน staging และ production และให้ `Last Update` ติดตามทุกฟิลด์ที่แก้ไขได้ ไม่มีค่าเริ่มต้นหรือการเดาชื่อจาก Agent งานใหม่ผ่านเว็บ/API/LINE ต้องมีชื่อ 1–180 ตัวอักษรหลังตัดช่องว่าง งานเดิมไม่ต้องย้ายข้อมูล การแก้ไขจากหน้าเว็บต้องระบุชื่อ; API edit รุ่นเก่าที่ไม่ส่งช่องนี้จะคงชื่อเดิมไว้ ไม่ต้อง migrate Neon และ rollback โค้ดได้โดยเก็บคอลัมน์ไว้

นำประเภทเก่า เอกสารกรมธรรม์, บริการลูกค้า, นัดหมาย, การเงิน และงานทั่วไป ออกจากตัวเลือก Airtable และตัวกรองเว็บ งานเดิมที่ค่าประเภทถูกล้างยังคงอยู่และแสดงเป็น **ไม่ระบุประเภท** โดยไม่เดาประเภทใหม่ให้ สามารถเลือกประเภทใหม่ใน Airtable ตามเนื้อหางานได้ ประวัติ Workflow ตัวแทนใหม่เดิมเปิดอ่านได้ในรายละเอียดงาน ไม่ลบหรือแปลงเครื่องหมายเสร็จให้ขั้นตอนใหม่โดยอัตโนมัติ เลขาตรวจและบันทึกรายการใหม่ตามข้อเท็จจริง

ตั้ง `Tasks.Category` ทั้ง staging และ production ให้เหลือ 4 ประเภทปัจจุบัน ประเภทวันเกิดตัวแทนและลูกค้าและงานเคลมเลิกใช้งานแล้ว สำรอง records ก่อนนำตัวเลือกเดิมออก เพราะ Airtable จะล้างค่าของงานที่ใช้ตัวเลือกนั้น ไม่ต้องเพิ่มตารางหรือ migration Neon; สถานะใหม่ใช้ `hvr_workflows` resource `case:<taskId>` และ `hvr_workflow_history` รุ่นข้อมูล 1 แยกจาก `task:<taskId>` เดิม

ก่อนปล่อยรัน lint, typecheck, unit/integration, API และ Playwright (`case-workflow.spec.ts`, `task-colors.spec.ts`) ตรวจมือถือและสำรองฐานข้อมูลก่อน deploy การ rollback โค้ดไม่ต้องลบประวัติใหม่

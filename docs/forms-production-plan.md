# แผนนำเอกสารและแบบฟอร์มขึ้น Production พร้อมค้นผ่าน LINE AI

วันที่ 13 พฤศจิกายน 2569 — สถานะ: กำลังพัฒนาและตรวจ Staging เพิ่ม migration 010–011 ใน Staging แล้ว ยังไม่เปิด Production ดูผลตรวจและงานค้างใน [สถานะคลังเอกสาร](forms-production-progress.md)

ใช้หน้ารายการกระชับที่ทดสอบใน Local เป็นฐาน เพิ่มการบันทึกข้อมูลถาวรและให้เว็บกับ “ถาม AI ผ่าน LINE” ค้นจากทะเบียนเอกสารชุดเดียวกัน เอกสารเปิดจากลิงก์ Allianz หรือ Google Drive เสมอ ระบบเก็บเฉพาะข้อมูลประกอบและ URL ไม่อัปโหลด คัดลอก ดาวน์โหลดมาเก็บ หรือเก็บเนื้อหาไฟล์ใน Neon/Vercel/n8n

## 1 ขอบเขตและพฤติกรรมที่เสนอ

- เพิ่มเมนู **เอกสารและแบบฟอร์ม** ที่ `/forms` ในเว็บจริง ใช้รายการแบบแถว ค้นหา กรองหมวด แบ่งหน้าละ 10 รายการ และแท็บ **★ ใช้บ่อย**
- นำเข้าทะเบียนประกันชีวิต 43 รายการจาก snapshot Local: แบบฟอร์มทั่วไป 22, ยูนิต ลิงค์ 14, ฝ่ายพิจารณา 2, FATCA & CRS 5 ไม่รวมส่วนประกันภัยและเอ็ทน่าเดิมในหน้าเว็บต้นทาง
- เอกสารที่เพิ่มเอง: กรอกชื่อ หมวด คำอธิบายการใช้งาน คำค้น/ชื่อเรียกอื่น แล้ววางลิงก์ Google Drive ตัดช่องอัปโหลด PDF และการสร้าง blob URL ออกจากหน้าจอจริง
- ใช้ปุ่ม **เปิดเอกสาร ↗** และระบุแหล่ง **Allianz / Google Drive** แทนการรับรองว่าจะดาวน์โหลด PDF โดยตรง ผู้ใช้ดูหรือบันทึกจากปลายทางตามสิทธิ์ของตน
- Admin และ Secretary (เลขา) ที่ Active เพิ่มรายการเอกสารและวางลิงก์ Allianz/Google Drive ได้ โดยบันทึกเป็นร่างก่อน เลขาดูและแก้ไขร่างที่ตนสร้างได้ ส่วน Admin จัดการร่างทั้งหมด ตรวจทาน เผยแพร่ เปลี่ยนฉบับ และพักใช้เอกสาร
- Agent ที่ Active ค้นและเปิดฉบับเผยแพร่ได้ แต่เพิ่มหรือแก้ไขเอกสารไม่ได้ ทุกบทบาทจัดรายการโปรดของตนได้
- รายการโปรดผูกกับบัญชีเว็บ เก็บใน Neon และใช้ร่วมกันได้ข้ามอุปกรณ์ ไม่ใช้ localStorage ร่วมกันระหว่างบัญชี และไม่ย้ายดาวทดลองของเครื่องนี้เข้าแต่ละบัญชีอัตโนมัติ
- เพิ่มเอกสารภายในได้โดยเลือกผู้เห็นเป็น “ทุกบัญชีที่ Active” หรือ “Admin/Secretary” โดยชื่อ คำอธิบาย และลิงก์ต้องถูกกรองตามสิทธิ์ทั้งเว็บและ AI

## 2 แหล่งข้อมูลและการจัดเก็บ

| ส่วน | แหล่งที่ใช้ | สิ่งที่เก็บ |
| --- | --- | --- |
| ทะเบียนเอกสาร | Neon เดิม | ID, ชื่อ, หมวด, คำค้น, คำอธิบาย, กลุ่มผู้เห็น, สถานะ, ฉบับปัจจุบัน |
| ฉบับเอกสาร | Neon เดิม | URL, แหล่งเอกสาร, ชื่อฉบับภายใน, วันที่เริ่มใช้ถ้าทราบ, ผู้ตรวจ/วันที่ตรวจ, ประวัติเปลี่ยนแปลง |
| รายการโปรด | Neon เดิม | environment + user ID + document ID แบบ unique |
| ประวัติการจัดการ | Neon เดิม | ผู้แก้ไข การเผยแพร่/พักใช้ และ revision ก่อน/หลัง โดยไม่เก็บไฟล์ |
| ไฟล์จริง | Allianz หรือ Google Drive | เจ้าของแหล่งเอกสารดูแลเอง ระบบเปิดลิงก์เท่านั้น |

เพิ่ม migration ถัดจาก `009` โดยตรวจเลขว่างตอนเริ่มพัฒนา แยก environment ทุกตาราง เสนอชื่อ `hvr_documents`, `hvr_document_versions`, `hvr_document_favorites`, `hvr_document_events` ใช้ service ฝั่งเว็บชุดเดียวสำหรับรายการ ค้นหา เปิดลิงก์ และตรวจสิทธิ์ ไม่เพิ่มทะเบียนซ้ำใน Airtable หรือตั้ง credential ฐานข้อมูลใหม่นอกเว็บ

การเผยแพร่ต้องทำใน transaction: ตรวจสิทธิ์และ revision → ตั้งฉบับปัจจุบัน → เก็บประวัติ → ล้างผลค้นหาที่ cache ไว้ การแก้ไขพร้อมกันต้องแจ้ง conflict ไม่ทับงานของผู้ดูแลอีกคน รายการโปรดอ้าง document ID จึงตามไปยังฉบับใหม่ได้

## 3 การเพิ่มลิงก์และอัปเดตฉบับ

ลำดับงาน: **เพิ่มรายการ/ฉบับใหม่ → บันทึกร่าง → เปิดตรวจปลายทาง → ยืนยันผู้เห็นและข้อมูล → เผยแพร่**

การเพิ่มรายการใหม่เริ่มได้จากทั้ง Admin และเลขา ร่างของเลขาส่งให้ Admin ตรวจและเผยแพร่ ก่อนเผยแพร่ต้องไม่ปรากฏในคลังของ Agent หรือผลค้น LINE AI ตรวจสิทธิ์เพิ่ม/แก้ไขร่างจากบัญชีที่ Login และผู้สร้างร่างฝั่งเซิร์ฟเวอร์ ไม่อาศัยเพียงการแสดงหรือซ่อนปุ่ม

1. รับเฉพาะ HTTPS ของโดเมนที่กำหนดไว้ เช่น Allianz/Azay และลิงก์แชร์ไฟล์ `drive.google.com` ลิงก์ประเภทอื่นให้แจ้งข้อผิดพลาด ไม่เปิดรับ URL ใด ๆ โดยไม่มีการตรวจ
2. สำหรับ Drive ให้เพิ่มลิงก์เป็นรายไฟล์ ไม่สแกนโฟลเดอร์ และไม่ขอ Drive OAuth/API เพิ่มในรุ่นแรก ผู้ดูแลตรวจว่าผู้รับจริงเปิดได้ก่อนเผยแพร่
3. สิทธิ์ใน RINLYN ควบคุมการเห็นทะเบียนและลิงก์ ส่วนสิทธิ์เปิดไฟล์ยังขึ้นกับ Drive: Restricted เปิดได้เฉพาะผู้ได้รับสิทธิ์; Anyone with the link เปิดได้ตามการแชร์ลิงก์ ตั้ง Viewer ตามผู้รับที่ต้องการ ไม่เปลี่ยนสิทธิ์ Drive อัตโนมัติ ดู [คู่มือ Google Drive](https://support.google.com/drive/answer/2494822?co=GENIE.Platform%3DDesktop&hl=en)
4. หากเปลี่ยนลิงก์หรือฉบับ ให้สร้าง revision แล้วเผยแพร่ใหม่ หน้าเว็บ/AI เลือกฉบับปัจจุบันเท่านั้น แสดง “ฉบับที่เผยแพร่ในระบบ” และวันที่ตรวจ ไม่อ้างว่าเป็นฉบับล่าสุดของบริษัทหากยังไม่มีหลักฐาน
5. ถ้าเจ้าของแก้ไฟล์ที่ URL เดิม เนื้อหาจะเปลี่ยนตามต้นทาง ประวัติใน RINLYN เป็นประวัติข้อมูลและลิงก์ ไม่ใช่สำเนาไฟล์เก่า หากต้องการให้ฉบับเก่าเปิดได้ ผู้ดูแลต้องคงไฟล์และลิงก์เดิมไว้ที่ต้นทาง
6. เอกสารที่พักใช้ถูกนำออกจากผลค้นหาและ AI ทันที รายการโปรดไม่เปิดฉบับที่พักใช้ และหน้าลิงก์เก่าแสดงว่าไม่พร้อมใช้งาน

ก่อนเปิดจริง ตรวจ 3 ลิงก์ที่ Local ติดป้าย “รอตรวจลิงก์”: รับเอกสารผ่านอีเมล, W-8BEN และ W-8BEN-E ความล้มเหลวของเครื่องมือไม่ได้ยืนยันว่าลิงก์เสีย หากยังตรวจไม่ได้ให้คงเป็นร่าง และรายงานจำนวนเผยแพร่จริงแทนการรับรองว่าพร้อมครบ 43 รายการ

## 4 ค้นเอกสารผ่านถาม AI ทาง LINE

ใช้ OA `@672vhuss` และ workflow n8n เดิม ไม่เพิ่ม OA และไม่เปลี่ยนเป็น AI Agent ขั้นตอนเป็น **LINE → เว็บตรวจผู้ใช้ → ค้นทะเบียน Neon → AI ช่วยจัดคำตอบ → เว็บตรวจผลและประกอบลิงก์ → LINE**

### การค้นและคำตอบ

- ใช้ฟังก์ชันค้นเดียวกับหน้าเว็บ ค้นชื่อ รหัสเอกสาร หมวด คำค้น และคำอธิบายที่ผู้ดูแลตรวจแล้ว รองรับคำเรียก เช่น “ใบหักบัญชี”, “ขอประวัติ”, “HC1”, “ฟอร์มเคลม OPD” โดยมี aliases สำหรับภาษาไทย ไม่พึ่งการตัดคำภาษาอังกฤษอย่างเดียว
- จัดอันดับชื่อ/รหัสตรงก่อน ตามด้วยคำค้นและคำอธิบาย ส่งผลที่เกี่ยวข้องประมาณ 3–5 รายการ พร้อมจำนวนที่พบและลิงก์ค้นต่อในเว็บ ไม่ส่งทั้งคลังไปให้โมเดลทุกคำถาม
- รุ่นแรกค้นข้อมูลประกอบเอกสาร ไม่อ่านข้อความภายใน PDF/Drive ไม่มี OCR, vector database หรือการส่งไฟล์ไปยัง OpenRouter คำถามเชิงเนื้อหาที่ไม่มีในคำอธิบายให้เปิดเอกสารหรือสอบถามผู้ดูแล ไม่แต่งเงื่อนไข/วิธีกรอก
- คำถามเอกสารล้วนไม่เรียกรายการ Tasks จาก Airtable แต่ยังตรวจบัญชี Active/role ตามระบบเดิม คำถามผสมงานกับเอกสารใช้เฉพาะงานที่ผู้ถามมีสิทธิ์
- คำสั่งตัวอย่าง: “ขอฟอร์ม HC1”, “มีเอกสารหักบัญชีไหม”, “เอกสารยูนิตลิงค์มีอะไรบ้าง”, “ขอเอกสารที่ฉันติดดาวไว้”, “ขอลิงก์รายการที่สอง”
- คำตอบแสดงชื่อ แหล่งเอกสาร ข้อความใช้งานสั้น ๆ ที่มีในทะเบียน และปุ่ม/ลิงก์ **เปิดเอกสาร** ใช้ลิงก์เว็บคงที่ `/forms/{id}` หรือ `/forms/{id}/open` ซึ่งตรวจสิทธิ์และเลือก URL ปัจจุบันอีกครั้ง แล้วเปิด Allianz/Drive โดยไม่ proxy ไฟล์ หากยังไม่ Login ให้กลับมารายการเดิมหลัง Login สำเร็จ
- หากพบหลายแบบที่อาจสับสน เช่น แบบฟอร์มยินยอมทั่วไปกับยูนิตลิงค์ ให้แสดงทางเลือกพร้อมหมวดและถามเพิ่ม หากไม่พบให้บอกตรง ๆ พร้อมลิงก์คลังเอกสาร
- Favorites ใน LINE เป็นการอ่านรายการโปรดของบัญชีเดียวกัน รุ่นแรกกดเพิ่ม/นำออกผ่านเว็บเท่านั้น

### จุดที่ต้องปรับในระบบเดิม

- `web/src/server/ai/context.ts`: แยก context งาน/เอกสาร/ผสม ให้ผลค้นพร้อม document ID, version ID, ข้อมูลที่เผยแพร่ และขอบเขตสิทธิ์
- `web/src/server/ai/line.ts`: เพิ่มการเลือกชนิดคำถามก่อนโหลดงาน และตรวจเอกสารอีกครั้งก่อนส่งคำตอบ ไม่ให้การถามเอกสารถูกนำไปแก้ร่างส่งงานที่ค้างอยู่ คำสั่งดูร่าง/ยกเลิก/ยืนยันเดิมยังทำงานตามเดิม
- `integrations/n8n/rinlyn-secretary-ai.json` และ generator ที่ใช้อยู่: ขยาย system prompt ให้ตอบเรื่องทะเบียนแบบฟอร์มได้ แต่ยังห้ามเปิดเผยเอกสารแนบเคสหรือข้อมูลส่วนตัว คง credential OpenRouter เดิมและเพิ่ม contract version เพื่อปล่อยเว็บกับ workflow อย่างเข้ากันได้
- ให้โมเดลคืน document IDs จากชุดที่เว็บอนุญาต เว็บตรวจ schema/ID/revision และสร้างชื่อกับ URL เอง ไม่เชื่อ URL ที่โมเดลแต่งหรือข้อความจาก memory ถ้า AI ขัดข้องยังตอบผลค้นหาแบบข้อความปกติได้
- `web/src/server/ai/memory.ts` และ migration: เพิ่ม document refs/version/order แยกจาก task refs เพื่อเข้าใจ “รายการที่สอง/ฉบับนี้” ตรวจสิทธิ์และสถานะล่าสุดทุกครั้ง หากเอกสารถูกพักใช้หรือเปลี่ยนฉบับ ต้องตัดข้อมูลเก่าที่ไม่ถูกต้องออก คงการล้างความจำและอายุบทสนทนาเดิม
- คงการตรวจ LINE signature, binding, Active/role, event deduplication และ single-use reply ticket ก่อน/หลังเรียก AI เอกสารหรือคำค้นไม่ใช่คำสั่งให้โมเดลเปลี่ยนสิทธิ์หรือเผยแพร่ข้อมูล

| 5 Staging | ทดสอบเว็บและ OA/credential ทดสอบแยกจาก Production | ผ่าน Admin/Secretary/Agent และ iPhone/Android/iPad จริง |
| 6 Production | สำรอง deploy แบบปิด flag ตรวจข้อมูล เปิดเว็บและ AI ตามลำดับ | ผ่าน smoke test จริงและมีทางปิด feature โดยงานเดิมยังทำงาน |

ชุดตรวจสำคัญ: favorites ไม่ข้ามผู้ใช้; ปิด Active/เปลี่ยน role/พักเอกสารขณะ AI ตอบ; เผยแพร่พร้อมกัน; query ภาษาไทย; ชื่อเอกสารซ้ำ; pagination; Google Drive ขอสิทธิ์/เลือกบัญชี; LINE เปิดลิงก์แล้วกลับหน้าที่ถูกต้อง; โมเดลส่ง ID/URL ปลอม; ล้าง memory ระหว่างตอบ; event ซ้ำไม่ส่งคำตอบซ้ำ; ค้นเอกสารขณะมีร่างงานโดยร่างไม่เปลี่ยน; สรุปงานและยืนยันสร้างงานเดิมไม่ถดถอย

รัน lint, typecheck, unit/integration tests ที่เกี่ยวข้อง, build และ Playwright การจำลอง viewport ไม่แทนการตรวจมือถือจริง ใช้ข้อมูลสมมติและฐานทดสอบ ไม่เพิ่มเคสทดสอบใน Production โดยไม่อยู่ในแผน smoke test

## 6 ขั้นตอนเปิด Production และย้อนกลับ

ก่อนเปิดจริงต้องผ่านการทดสอบสิทธิ์เพิ่มเอกสาร: Admin/เลขาที่ Active สร้างร่างได้, Agent และบัญชี Inactive ถูกปฏิเสธแม้เรียก API โดยตรง, เลขาแก้ร่างของเลขาคนอื่นหรือเผยแพร่เองไม่ได้ และร่างไม่หลุดเข้าผลค้น LINE AI

1. สำรอง Neon และ export workflow n8n ปัจจุบัน ตรวจ branch/deployment/credentials ให้ตรง production ก่อนดำเนินการ
2. เพิ่ม schema แบบ additive และเปิด feature flags ใหม่เป็น false เช่น `FORMS_ENABLED` กับ `AI_FORMS_ENABLED` โค้ดเก่ายังใช้งานฐานข้อมูลได้
3. Deploy เว็บที่รองรับ context ใหม่แต่ยังปิด feature นำเข้าทะเบียนเป็นร่าง ตรวจจำนวน/URL/สิทธิ์ แล้วเผยแพร่เฉพาะรายการที่ผ่าน ห้าม seed ทับฉบับที่ Admin แก้ไว้
4. เปิดเมนูเว็บ ทดสอบบัญชีจริง เปิด Allianz/Drive และ Favorites จากนั้นเผยแพร่ n8n รุ่นที่รองรับทั้งงานเดิมกับเอกสาร แล้วเปิด AI document flag
5. ทดสอบบน OA จริงกับบัญชีที่ผูกแล้ว: ขอ HC1, ขอเอกสาร Drive, ถามต่อ, ขอรายการโปรด, เอกสารที่ไม่มีสิทธิ์ และสรุปงานเดิม ตรวจว่าแต่ละ event มีคำตอบเดียว
6. เฝ้าดูข้อผิดพลาดค้นหา/เปิดลิงก์/ตอบ LINE และผลที่ไม่พบ โดย log เฉพาะข้อมูลที่จำเป็น ไม่เก็บไฟล์ credential หรือเนื้อหาเคสใน log ประเมินเวลาตอบและการใช้ Neon/OpenRouter จากผลจริง
7. หาก AI มีปัญหา ปิด `AI_FORMS_ENABLED` และคืน workflow ที่เข้ากันได้กับเว็บ หากเว็บมีปัญหา ปิด `FORMS_ENABLED` เพิ่ม คงทะเบียน/รายการโปรด/ประวัติไว้ ไม่ drop ตารางหรือ restore ทั้งฐานจนทับงานใหม่ของผู้ใช้

## 7 สิ่งที่ยังไม่รวมในรุ่นแรก

- ตรวจเว็บไซต์ Allianz/Drive และเผยแพร่ฉบับใหม่โดยอัตโนมัติ ผู้ดูแลเป็นคนตรวจและเปลี่ยนลิงก์
- อ่าน สรุป หรือค้นข้อความภายในไฟล์ รวมถึงการให้ AI กรอกแบบฟอร์ม
- อัปโหลดไฟล์ เก็บสำเนาไฟล์ สแกนทั้ง Drive หรือปรับสิทธิ์แชร์ไฟล์แทนผู้ดูแล
- เปลี่ยน OA แจ้งเตือนงาน `@688rmrty` หรือเปลี่ยน AI เป็น Agent

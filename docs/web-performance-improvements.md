# ลดเวลารอโหลดเว็บโดยคงข้อมูลและสิทธิ์เดิม

วันที่: 24 พฤศจิกายน 2569 (2026-11-24)

สถานะ: พัฒนาและทดสอบบนเครื่องผ่านแล้ว ยังไม่ได้ Deploy และไม่ได้เรียกฐานข้อมูลหรือ API ของ Production ในรอบพัฒนานี้

## ปัญหาที่แก้

การเข้า Space และสลับหน้าเรียกตรวจสิทธิ์ Control Base ซ้ำภายในคำขอเดียว ส่วนรายละเอียดงานเดิมเรียก `/api/bootstrap?scope=context` แล้วจึงเรียก `/api/tasks/:id` ทำให้ตรวจผู้ใช้และสมาชิกครบชุดสองรอบ นอกจากนี้หน้า Workspace นำเข้าโค้ดเอกสาร LINE และ workflow ตั้งแต่เริ่มต้น แม้ยังไม่ได้เปิดส่วนเหล่านั้น

## การเปลี่ยนแปลง

- เพิ่ม `RequestReadScope` เพื่อรวมการอ่าน Airtable ที่เหมือนกันภายใน HTTP request เดียว แยกตาม repository, table, record, formula และ fields ไม่มี cache ส่วนกลางหรือการแชร์ข้อมูลระหว่างคำขอ ผู้ใช้ หรือ Base
- เปิดใช้เฉพาะ GET bootstrap และรายละเอียดงานผ่าน `readRoute` คำขอใหม่ตรวจ Active, role, membership และ Base binding ใหม่เสมอ เส้นทางบันทึกงาน/OAuth/LINE เดิมไม่ได้เปิดใช้ cache นี้
- การเขียนผ่าน repository จะล้าง scope ทั้งชุดก่อนและหลังคำขอ รวมกรณีผลเขียนไม่แน่นอน เพื่อรองรับการสร้างตัวเชื่อม Owner ที่มีอยู่เดิม
- ปิดและล้าง scope เมื่อจบคำขอทั้งสำเร็จและล้มเหลว งาน LINE ที่รันผ่าน `after()` จึงอ่านสิทธิ์ล่าสุด ไม่ใช้ snapshot ของหน้าเว็บ
- เพิ่ม `GET /api/bootstrap?scope=context&taskId=rec...` ส่งข้อมูลพื้นฐานและรายละเอียดงานในคำขอเดียว ตรวจเจ้าของงานก่อนอ่านประวัติ/ติดตาม และไม่โหลดรายการงานทั้งหมดสำหรับหน้ารายละเอียด
- endpoint รายละเอียดเดิมยังใช้ได้ หน้าเว็บมี fallback สำหรับ backend เดิมระหว่างเปลี่ยน deployment
- อ่านรายการงานกับรายชื่อผู้ใช้พร้อมกัน และอ่านประวัติกับติดตามพร้อมกันหลังตรวจสิทธิ์งาน โดยยังใช้ตัวจำกัดอัตรา Airtable เดิม
- แยกโหลดโค้ดเอกสาร การตั้งค่า LINE การแก้ข้อมูลงาน และ workflow เมื่อเปิดใช้ พร้อมข้อความรอโหลด
- ย้าย DM Sans และ Noto Sans Thai มาเป็น WOFF2 ภายในแอปผ่าน `next/font/local` พร้อมใบอนุญาต OFL ตัด CSS import จาก Google Fonts; build และผู้ใช้ไม่ต้องเรียก Google เพื่อโหลดฟอนต์
- จำกัด `private, no-store` ให้หน้าเว็บ/API/redirect ข้อมูล ส่วนไฟล์ build ที่มี hash ใต้ `/_next/static/` ใช้นโยบาย cache ของ Next เพื่อให้ JS, CSS และฟอนต์นำกลับมาใช้ได้ การตรวจ HTTP บน localhost พบว่ากฎเดิมครอบไฟล์ฟอนต์ด้วย `no-store`
- เพิ่ม `Server-Timing` แยก `auth` และ `data` ในคำตอบ GET ที่สำเร็จ เป็นเวลาเท่านั้น ไม่มีข้อมูลผู้ใช้หรือ secret

## หลักฐานและขอบเขตผล

integration fixture ของผู้จัดการที่ไม่ใช่ System Owner เปรียบเทียบการเปิดรายละเอียดหนึ่งงาน:

| ตัววัด | เดิม | รุ่นปรับปรุง |
| --- | --- | --- |
| คำขอข้อมูลจากเบราว์เซอร์ | bootstrap แล้ว detail รวม 2 คำขอ | bootstrap พร้อม detail 1 คำขอ |
| จำนวนการเรียก Airtable repository ใน fixture | 20 | 9 |
| ข้อมูลพื้นฐานและรายละเอียดที่ได้รับ | baseline | ตรงกับ baseline ยกเว้นเวลา sync |
| การเขียน records ระหว่าง scenario | ไม่มี | ไม่มี |

ตัวเลข 20 → 9 คือจำนวนการเรียกในข้อมูลจำลองที่แต่ละชุดไม่เกินหนึ่งหน้า ไม่ใช่เวลา Production และไม่ใช่การรับรองว่าเว็บเร็วขึ้น 55% ทุกหน้า ผลจริงขึ้นกับจำนวนงาน สมาชิก เครือข่าย การเริ่ม server และคิวของ Base

การทดสอบเบราว์เซอร์ก่อนย้ายฟอนต์พบ timeout 3 กรณีขณะรอ `load`/`reload` บันทึก network พบ Google Fonts CSS ค้าง และไฟล์ฟอนต์หนึ่งรายการใช้ประมาณ 27.4 วินาที นี่เป็นหลักฐานของการพึ่งเครือข่ายภายนอกบนเครื่องทดสอบ ไม่ใช่เวลาที่วัดจากอุปกรณ์ของผู้ใช้ เพิ่ม regression ให้บล็อก Google Fonts แล้วตรวจว่าฟอนต์ไทย/อังกฤษโหลดจาก localhost สำเร็จ

รอบนี้คงรายการสรุปงานครบสำหรับ Dashboard, ตัวกรอง และปฏิทิน ไม่ตัดข้อมูลเหลือเพียง 7 งานจนยอดรวมผิด และไม่เก็บข้อมูลข้ามคำขอเพื่อแสดงก่อนตรวจสิทธิ์ การแบ่งหน้าฝั่งเซิร์ฟเวอร์พร้อมยอดรวม/ค้นหาทั้งชุดยังเป็นงานต่อยอดหากผลวัดหลังปรับชุดนี้ไม่เพียงพอ

## การตรวจสอบก่อนนำขึ้นบริการ

- Unit: รวมการอ่านพร้อมกัน, clone ไม่ให้ผู้เรียกแก้ snapshot ของกันและกัน, แยก Base ที่มี record ID ซ้ำ, แยก formula/fields, invalidation เมื่อเขียน, ปิด cache ก่อนงานเบื้องหลัง
- Integration: เทียบจำนวน call และข้อมูลก่อน–หลัง, ไม่มี record mutation, ถอนสมาชิก/ปิดผู้ใช้/พัก Space มีผลในคำขอถัดไป, Agent อ่านงานคนอื่นหรือประวัติไม่ได้
- Browser: หน้ารายละเอียดแบบ scoped ใช้คำขอเดียว และไม่แสดงงานเดิมหลังถูกปฏิเสธสิทธิ์ รวม regression ของหน้าและฟอร์มที่โหลดโค้ดแยก
- ตรวจ lint, typecheck, unit, PGlite integration, production build และ Playwright บน localhost; ใช้ fixture ไม่ใช้ credentials จริง

| การตรวจ | ผล |
| --- | --- |
| Lint / Typecheck / Production build | ผ่าน; lint มีคำแนะนำระดับ info แต่ไม่มี error/warning |

ตรวจภาพ Dashboard บน desktop และฟอร์มบน mobile emulation ว่าฟอนต์ไทย/อังกฤษแสดงได้ หลักฐานการทดสอบอยู่ใน ignored `web/test-results/performance-*.log`; trace ที่พบปัญหาฟอนต์เดิมเก็บใน ignored `artifacts/performance-before-fonts/` ไม่ใช้ผล browser emulation แทนการตรวจอุปกรณ์จริงหรือผลความเร็ว Production

## แนวทางเปิดใช้งานภายหลัง

1. นำเฉพาะโค้ดและเอกสารที่เกี่ยวข้องขึ้น Staging ที่แยกจาก Production เมื่อได้รับคำสั่งให้ Deploy
2. เปรียบเทียบ Dashboard, รายการงาน และรายละเอียดงานก่อน–หลังด้วยบัญชีทดสอบเดิม บันทึก `Server-Timing`, จำนวน request, เวลาแสดงงาน และ p50/p95 แยกโหลดครั้งแรก/ครั้งถัดไป รวมหลายผู้ใช้พร้อมกันตามงบทดสอบ
3. ยืนยันข้าม Space, ถอนสิทธิ์, งานของ Agent คนอื่น, ฟอร์มแก้ไข และการแจ้ง LINE ด้วยข้อมูลทดสอบ ให้ผลเวลาเป็นหลักฐานก่อนอ้างว่าปัญหา Production หายแล้ว
4. การเปิดใช้โค้ดชุดนี้ไม่ต้อง migration, ย้ายข้อมูล, เปลี่ยน schema Airtable หรือหมุน credentials ใช้กระบวนการ release ปกติ และ rollback deployment ได้โดยไม่ย้อนฐานข้อมูล

ยังไม่มีการ commit/push/Deploy จากเอกสารนี้ และไม่มีการเปลี่ยนข้อมูล งาน สมาชิก หรือ configuration ของ Production

# Workflow งานตัวแทนใหม่

เลือกประเภทงาน **ตัวแทนใหม่** ในหน้าส่งงาน จากนั้นเปิดรายละเอียดงานเพื่อใช้ “เส้นทางตัวแทนใหม่” งานประเภทอื่นใช้ขั้นตอนเดิม

## เลขาฯ ติดตามอย่างไร

1. บันทึกวันที่แจ้งอบรม และติ๊กเมื่อผู้สมัครรับทราบ
2. บันทึกรอบ/วัน/สถานที่อบรม พร้อมสถานะจองหรือเข้าอบรมแล้ว เลือก “อบรมพร้อมสอบ” ได้
3. เพิ่มรอบสอบ บันทึกวันและผล หากไม่ผ่านหรือเลื่อน ให้เพิ่มรอบใหม่โดยรักษารอบเดิมไว้ ตัวเลือกอบรมพร้อมสอบเติมวันที่ตอนเพิ่มรอบเท่านั้น ตรวจวันสอบก่อนบันทึก
4. หลังสอบผ่าน เพิ่มเอกสารเฉพาะเคส บันทึกวันที่ขอ/ได้รับ และยืนยันว่าเอกสารครบ ถ้าไม่มีรายการมาตรฐานต้องตรวจรายการที่ต้องใช้จริงก่อนยืนยัน
5. บันทึกวันที่ยื่นออกรหัส รหัสตัวแทนที่ได้รับ และวันที่ได้รับรหัส
6. ติดตาม Smart Start, Training 2, Training 3 และ Training 4 แยกกัน เรียนต่างลำดับได้

แต่ละส่วนมีวันติดตามและหมายเหตุภายใน กด **บันทึก Workflow** ก่อนออกจากหน้า การบันทึกไม่เปลี่ยนสถานะงานหลักโดยอัตโนมัติ ต้องทำครบทุกขั้นตอนก่อนเลือกสถานะ “เสร็จสิ้น” ได้ หากงานปิดแล้ว ให้เปิดงานอีกครั้งก่อนแก้รายละเอียด

หน้า “งานที่ต้องติดตาม” ของเลขาฯ ใช้วันใกล้ที่สุดจากนัดเดิมและ Workflow วันที่อบรม/สอบที่ยังไม่เสร็จใช้เป็นวันติดตามเมื่อไม่ได้ระบุวันติดตามแยก เมื่อจบรายการนั้นแล้วจะเลือกวันของรายการถัดไป อบรมที่ยังไม่จองและไม่มีวันติดตามจะแสดงว่ายังค้างใน Workflow แต่ไม่ปรากฏเป็นนัดในปฏิทิน

## Admin ตั้งรายการภายหลัง

ไปที่ **ทีมของเรา → ตั้งค่า Workflow ตัวแทนใหม่** เพื่อเปลี่ยนชื่อ Module หรือเพิ่มชุดเอกสารเริ่มต้น ไม่ต้อง Deploy ใหม่ การเปลี่ยนชื่อ Module ใช้รหัสภายในเดิมและรักษาผลอบรมไว้ รายการที่เพิ่มใหม่มีผลกับเคสที่ยังไม่เคยบันทึก Workflow; เคสเดิมรักษารายการเดิมและเพิ่มเอกสารเฉพาะเคสได้ ไม่ลบ Module เดิมเพื่อป้องกันประวัติสูญหาย

Agent เห็นเฉพาะสรุปขั้นตอนและสถานะ Module ของงานตัวเอง เลขาฯ/Admin เห็นรายละเอียด หมายเหตุ และประวัติ 50 การบันทึกล่าสุด ประวัติฉบับเต็มเก็บในฐานข้อมูล การออกรหัสในหน้านี้เป็นการบันทึกรหัสที่ได้รับ ไม่ได้สร้างบัญชี Users หรือเปลี่ยนสิทธิ์ Login

## Deployment และข้อมูล

- รัน migration `004_onboarding.sql` ก่อน Deploy เพิ่ม `hvr_workflows` และ `hvr_workflow_history` ใน Neon แยก environment ไม่เปลี่ยน schema Airtable
- สำรอง Neon ต้องรวมทั้งสองตารางและ migration history; Airtable export อย่างเดียวไม่ครอบคลุมรายละเอียด Workflow
- บันทึก state และ audit ใน SQL statement เดียว ใช้ version ป้องกันบันทึกทับ และ operation key ป้องกันซ้ำ ใช้ task reservation เดียวกับการเปลี่ยนสถานะหลัก
- การตรวจครบขั้นตอนบังคับที่ API เว็บ การแก้ Status โดยตรงใน Airtable อยู่นอกข้อบังคับนี้ ควรอัปเดตผ่านเว็บ
- Rollback โค้ดได้โดยเก็บตารางใหม่ไว้ แต่รุ่นเก่าไม่แสดง Workflow และไม่มีเงื่อนไขปิดงาน จึงควรพัก writes หาก rollback แล้วต้องรักษาเงื่อนไขนี้
- ข้อความหมายเหตุ/ข้อมูลเอกสารเก็บเฉพาะรายละเอียดติดตาม ไม่อัปโหลดไฟล์เอกสารใน Workflow ใช้ช่องเอกสารอ้างอิงของงานตามเดิม

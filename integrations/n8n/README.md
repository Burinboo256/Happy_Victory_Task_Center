# RINLYN Secretary LINE AI

ช่องถามและส่งงานสำหรับ OA `@672vhuss` ผู้ใช้พิมพ์ถามสถานะ สรุปวันนี้ หรือจัดร่างส่งงาน ไม่มี Schedule Trigger และใช้ระบบแจ้งเลขาของ OA เดิมเมื่อสร้างงานสำเร็จ

## ส่งงานผ่าน LINE

1. เชื่อมบัญชีเว็บกับ OA แล้วพิมพ์ “ส่งงานลูกค้าใหม่ ติดตาม Memo คุณสมชาย ด่วนมาก กำหนดส่งพรุ่งนี้”
2. AI จัดร่างและถามข้อมูลที่ยังขาดทีละข้อ Admin/Secretary ต้องระบุชื่อ Agent เจ้าของงาน ส่วน Agent ส่งงานของตนเองเท่านั้น
3. ตรวจชื่องาน รายละเอียด ประเภท เจ้าของ ความเร่งด่วน และวันที่จริง (เวลาไทย) กด **ยืนยันสร้างงาน** จึงบันทึกเป็นงานเข้าใหม่
4. กด **แก้ไข** แล้วพิมพ์สิ่งที่เปลี่ยน หรือกด **ยกเลิก** ได้ พิมพ์ “ดูร่าง” เพื่อเรียกปุ่มกลับมา ร่างมีอายุ 30 นาที
5. ระบบตอบรหัสงานและลิงก์ติดตาม เลขาที่เปิดรับแจ้งเตือนจะได้รับผ่านระบบแจ้งงานเดิม

รองรับข้อความก่อน ยังไม่รับไฟล์หรือเสียงเพื่อสร้างงาน การพิมพ์คำว่า “ยืนยันสร้างงาน” จะแสดงร่างให้กดปุ่ม ไม่สร้างทันที หากระบบแจ้งว่ากำลังตรวจสอบ ให้กดตรวจผลคำขอเดิมหรือตรวจในเว็บก่อนส่งใหม่

โมเดลแก้ได้เฉพาะร่าง ไม่มีสิทธิ์เรียกเขียนงาน ปุ่มผูกกับผู้ใช้ LINE, binding, รุ่นร่างและลายเซ็นของเซิร์ฟเวอร์ ทุกครั้งที่ยืนยันจะตรวจ Active/role/เจ้าของ/runtime write gate ใหม่ ใช้ Journal และ Request Key เดียวกับเว็บ การยืนยันซ้ำจึงใช้ operation เดิม รวมถึงกรณี Airtable ตอบกลับไม่แน่นอน

ร่างเก็บใน Neon (`008_ai_task_drafts.sql`) ข้อมูลร่างที่หมดอายุถูกล้างเมื่อมีคำขอร่างถัดไป และลบแถวที่สิ้นสุดหลังหมดอายุเกินหนึ่งวัน คำขอที่ยืนยันแล้วแต่ยังตรวจสอบจะเก็บไว้จน recovery เสร็จ การสรุปยังใช้เฉพาะข้อมูลที่ฉายออกมาเดิม ส่วนการจัดร่างส่งข้อความและรายละเอียดที่ผู้ใช้พิมพ์กับชื่อ Agent ที่เลือกได้ผ่าน n8n/OpenRouter

## ความจำบทสนทนา (HTTP Request เดิม)

พิมพ์ “สถานะ HVR-00001” แล้วถามต่อ “แล้วเคสนี้กำหนดส่งวันไหน” ได้ ระบบส่งประวัติคำถาม–คำตอบที่ส่งสำเร็จล่าสุดไม่เกิน 6 รอบ อายุรอบละ 30 นาทีไปกับบริบท ไม่ใช้ AI Agent และไม่มีเครื่องมือเขียนข้อมูลให้โมเดล

- เก็บใน Neon แยก environment/บัญชี/การผูก LINE/role ไม่ใช้ n8n workflow static data; เปลี่ยน role หรือผูกใหม่จะเริ่มความจำใหม่ ยกเลิกการเชื่อมจะลบผ่าน foreign key
- ประวัติใช้ระบุเคสเท่านั้น อ่านสิทธิ์และสถานะล่าสุดจาก Airtable ทุกครั้ง หากเคสในประวัติหมดสิทธิ์จะตัดรอบนั้นออก คำถามระบุรหัสใหม่หรือขอสรุปมีลำดับเหนือเคสเดิม ถ้าคำว่า “เคสนั้น” อาจหมายถึงหลายเคส ให้ถามรหัสเพิ่ม
- จำเฉพาะคำตอบที่ LINE รับแล้ว เรียงตามลำดับคำขอที่เตรียมเข้าโมเดล ไม่เรียงตามเวลาที่โมเดลตอบกลับ คำตอบล้มเหลว/รอส่งไม่เป็นความจำ
- พิมพ์ **ล้างความจำ** หรือ **เริ่มคุยใหม่** เพื่อลบประวัติและยกเลิกคำตอบเก่าที่ยังไม่เริ่มส่ง ไม่ลบงานหรือร่าง ใช้ “ยกเลิก” หากต้องการยกเลิกร่าง
- หมดอายุแล้วจะไม่ถูกใช้ ลบจากฐานข้อมูลเมื่อมี webhook ถัดไป (ไม่มี cron เพิ่ม) จำกัดคำถาม 2,000/คำตอบ 4,500 ตัวอักษรต่อรอบ สำเนา backup และข้อมูลที่ผู้ให้บริการได้รับเป็นไปตามการเก็บข้อมูลของแต่ละระบบ
- ความจำการถามงานไม่ถูกนำไปแก้ร่างหรือกดยืนยันงาน; ร่างใช้ state และปุ่มยืนยันเดิม ระหว่างมีร่างเปิดอยู่ใช้ “สรุป…”/“สถานะ…” เพื่อถามงาน หรือยกเลิกร่างก่อนถามต่ออิสระ

## เส้นทางคำขอ

LINE → n8n Webhook (raw body) → `/api/ai/line` ตรวจลายเซ็น/บัญชี/สิทธิ์ → OpenRouter เรียบเรียง → `/api/ai/reply` ตรวจสิทธิ์ล่าสุดและส่งกลับด้วย reply token ของเหตุการณ์นั้น

n8n ตอบรับ LINE ทันทีเพื่อหลีกเลี่ยง timeout ตอนเว็บ/ฐานข้อมูลเริ่มทำงาน การ Verify ของ LINE ยืนยันเพียงว่า webhook รับคำขอได้ ต้องทดสอบเชื่อมบัญชีและถามงานจริงด้วย ลายเซ็นยังต้องผ่านก่อนอ่านข้อมูลหรือเรียกโมเดล

- เชื่อมบัญชีที่ `/notifications` ด้วยรหัส `RINAI` อายุ 10 นาที แล้วกลับมายืนยันชื่อ LINE ในเว็บ
- เก็บการเชื่อม OA ใหม่ในตาราง `hvr_ai_*` แยกจาก OA แจ้งเตือน
- Agent อ่านเฉพาะงานเจ้าของบัญชี Admin/Secretary อ่านตามสิทธิ์เว็บ
- ตรวจ Active, role, binding และความเป็นเจ้าของอีกครั้งก่อนตอบ Agent
- ไม่ส่ง Description, ข้อความอัปเดต, เอกสารแนบ, หมายเหตุ หรือค่าข้อมูลประกอบเคสไปยังโมเดล ชื่องาน/ชื่อเจ้าของ/สถานะ/ความคืบหน้าและวันติดตามยังเป็นส่วนของบริบท
- ยอดรวมคำนวณฝั่งเว็บตามวันประเทศไทย รายการแสดงสูงสุด 60 งาน พร้อม `matched`, `included`, `truncated` ให้โมเดลแจ้งข้อจำกัด ผู้ใช้ระบุรหัส HVR เพื่อหาเคสเฉพาะได้

## ติดตั้ง

1. สำรอง Neon และรัน migration ถึง `009_ai_conversation_memory.sql` ผ่าน `npm run db:migrate` ด้วย environment ที่ถูกต้อง
2. ตั้งค่า Vercel แบบ server-only: `AI_LINE_CHANNEL_SECRET`, `AI_LINE_CHANNEL_ACCESS_TOKEN`, `AI_LINE_OA_ID=@672vhuss`, `AI_LINE_ENABLED=true` แล้ว deploy หากไม่กำหนด `AI_LINE_BOT_USER_ID` ระบบตรวจตัวตน OA ด้วย LINE bot info และ cache 5 นาที
3. สร้างไฟล์ด้วย `node tools/build-n8n-ai.mjs` และนำ `rinlyn-secretary-ai.json` เข้า workflow ว่าง
4. ใน node OpenRouter เลือก Header Auth credential: Name `Authorization`, Value `Bearer <API key>`, Allowed Domains `openrouter.ai` เก็บ key ใน Credentials เท่านั้น
5. ตรวจ Settings: timezone `Asia/Bangkok`, ไม่เก็บ successful/failed/manual execution data และไม่เก็บ execution progress การ import บางเวอร์ชันอาจไม่คัดลอก settings ต้องตรวจใน UI
6. Publish แล้วตั้ง LINE webhook เป็น `https://rinlyn.app.n8n.cloud/webhook/rinlyn-secretary-ai` หลังยืนยันเลิกใช้ webhook เดิมของ OA นี้ เปิด Use webhook และตรวจ Verify
7. เชื่อมบัญชีทดสอบแล้วถาม “สรุปงานวันนี้”, “งานไหนเกินกำหนด”, “สถานะ HVR-00001” เปรียบเทียบกับเว็บ ทดสอบ Agent สองบัญชีและบัญชี inactive

## การตอบและการดูแล

ใช้ `openai/gpt-6.1-sol` ผ่าน OpenRouter โดยตั้ง reasoning effort เป็น `low` สำหรับถามสถานะและสรุปงาน ไม่ส่ง `temperature` ซึ่งไม่รองรับเมื่อใช้ reasoning และจำกัด `max_tokens=4096` รวม reasoning กับคำตอบ เปลี่ยน model ได้ที่ node เดิม โดยคงคำสั่งเรื่องสิทธิ์และขอบเขตข้อมูลไว้ ตั้ง `provider.data_collection=deny` หาก API/เครดิต/โมเดลขัดข้องจะตอบให้ลองใหม่ ไม่สร้างคำตอบจากข้อมูลที่โหลดไม่ครบ

ยอมรับเฉพาะข้อความส่วนตัวที่มีลายเซ็นถูกต้องและเหตุการณ์ภายใน 2 นาที เหตุการณ์ซ้ำไม่เรียกโมเดลซ้ำ Reply ticket เป็นค่าแบบสุ่ม เก็บเฉพาะ hash และใช้ครั้งเดียว ตรวจซ้ำก่อนส่ง ไม่มีสิทธิ์เลือกผู้รับเอง

จำกัด 10 เหตุการณ์/LINE/นาที และ 1,000 เหตุการณ์รวม/วัน เก็บ metadata กันซ้ำไม่เกินประมาณหนึ่งวัน (ล้างเมื่อมี webhook ถัดไป) ล้าง reply token หลังส่งหรือส่งล้มเหลว เก็บคำถาม/คำตอบสรุปใน Neon ตามขอบเขตความจำข้างต้น ส่วนข้อมูลร่างและข้อความยืนยันเก็บตามอายุร่าง/เหตุการณ์ข้างต้น หากผลส่งไม่แน่ชัดให้ผู้ใช้ถามใหม่ ไม่ retry node ส่งเอง

หยุดบริการด้วย `AI_LINE_ENABLED=false` และ redeploy หรือ unpublish workflow การ rollback ไม่ต้องลบตาราง และไม่กระทบ OA แจ้งเตือนเดิม
